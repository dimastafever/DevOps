## Теория

### SSH (Secure Shell)

**SSH** — протокол прикладного уровня для защищённого удалённого доступа к командной оболочке
и выполнения команд на удалённом компьютере. Все данные (включая пароли) передаются
в зашифрованном виде, поэтому SSH — основной инструмент системного администратора.

SSH работает по модели «клиент-сервер»:

- **SSH-сервер** (демон `sshd`) слушает порт **22** (по умолчанию).
- **SSH-клиент** (`ssh`) устанавливает зашифрованное соединение с сервером.

### Основные шаги настройки SSH-сервера

1. **Установка сервера:**
   ```
   sudo apt install openssh-server
   ```

2. **Проверка статуса службы:**
   ```
   sudo systemctl status ssh
   ```

3. **Конфигурационный файл** `/etc/ssh/sshd_config`:
   ```
   Port 22
   PermitRootLogin no
   PasswordAuthentication yes
   ```

4. **Перезапуск службы после изменений:**
   ```
   sudo systemctl restart ssh
   ```

5. **Проверка порта:**
   ```
   ss -tlnp | grep 22
   ```

### Подключение клиента

Клиент подключается командой:
```
ssh пользователь@хост
```

Пример:
```
ssh adv@192.168.1.10
```

При первом подключении необходимо подтвердить ключ хоста:
```
The authenticity of host '192.168.1.10' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
```

После этого вводится пароль пользователя.

### Аутентификация по ключам

Более безопасный способ — аутентификация по SSH-ключам:

1. **Генерация пары ключей на клиенте:**
   ```
   ssh-keygen -t rsa -b 4096
   ```

2. **Копирование публичного ключа на сервер:**
   ```
   ssh-copy-id adv@192.168.1.10
   ```

3. **Проверка входа:**
   ```
   ssh adv@192.168.1.10
   ```

При этом пароль вводить больше не нужно — вход происходит по ключу.

### Завершение сеанса

Выход из SSH-сессии:
```
exit
```
