## Теория

### DNS (Domain Name System)

**DNS** — служба, преобразующая имена компьютеров (доменные имена) в IP-адреса и обратно.
Работа DNS основана на иерархической системе зон.

Когда клиент хочет обратиться к компьютеру по имени (например, `adv-server`), он сначала
спрашивает DNS-сервер: «Какой IP-адрес у этого имени?».

### Файл /etc/resolv.conf

Файл `/etc/resolv.conf` на клиенте задаёт, какие DNS-серверы использовать:

```
nameserver 192.168.1.10
search adv.local
```

- **`nameserver`** — IP-адрес DNS-сервера.
- **`search`** — суффикс, который добавляется к коротким именам.

### BIND и его конфигурация

**BIND** (Berkeley Internet Name Domain) — наиболее популярный DNS-сервер в Linux. В Debian/Astra
Linux его конфигурация находится в `/etc/bind/`.

Основные файлы:

| Файл | Назначение |
|------|------------|
| `named.conf` | Основной конфигурационный файл |
| `named.conf.local` | Локальные зоны |
| `named.conf.options` | Параметры работы сервера |
| `db.local` | Локальная зона `localhost` |

### Права на директорию

Команды из файла:

```
sudo chown -R bind:bind /etc/bind
sudo chmod -R 777 /etc/bind
```

- **`chown -R bind:bind`** — рекурсивно назначает владельца и группу `bind` для всех файлов
  в `/etc/bind`.
- **`chmod -R 777`** — рекурсивно выдаёт всем права на чтение, запись и выполнение.

> ⚠️ Режим `777` — это небезопасная практика для продакшена, но в учебной среде часто
> используется для упрощения отладки.

### Проверка include в named.conf.local

В `named.conf.local` часто должна присутствовать директива, подключающая ключ для
управления сервером:

```
include "/etc/bind/rndc.key";
```

Без этого ключа сервер может не запуститься или не принимать команды управления
(например, `rndc reload`).

### Проверка работы DNS

Сначала проверяется доступность сервера:
```
ping 192.168.1.10
```

Затем — разрешение имени:
```
nslookup adv-server
dig adv-server
```
