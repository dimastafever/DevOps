# АЛВС1 — Пользователи и серверы в Linux

## Что находится в файле

Файл `АЛВС1.docx` — это первая лабораторная работа курса. В нём зафиксированы команды настройки
пользователей и серверных ролей в Linux (дистрибутив Astra Linux / Debian-подобный).

Содержимое файла:

```
sudo adduser adv

adv-server
advc1 - client1
advc2 - client2

2+

3

sudo rm -rf /.
```

Ключевые элементы файла:

| Элемент | Описание |
|---------|----------|
| `sudo adduser adv` | Команда создания пользователя `adv` с правами администратора |
| `adv-server` | Имя сервера (роль) |
| `advc1 - client1` | Первый клиентский компьютер |
| `advc2 - client2` | Второй клиентский компьютер |
| `2+`, `3` | Пометки о шагах выполнения |
| `sudo rm -rf /.` | Команда полного удаления файловой системы — показана как антипример/шутка |

## Теория

### Создание пользователей в Linux

Команда `sudo adduser adv` создаёт нового пользователя в системе. Разберём её компоненты:

- **`sudo`** — утилита запуска команды от имени суперпользователя (root). Требуется для операций,
  изменяющих системные файлы.
- **`adduser`** — более дружелюбная обёртка над низкоуровневой командой `useradd`. Она автоматически:
  - создаёт домашнюю директорию (`/home/adv`),
  - создаёт группу с именем пользователя,
  - задаёт оболочку по умолчанию (например `/bin/bash`),
  - запрашивает пароль и дополнительную информацию интерактивно.

Альтернативная низкоуровневая команда:
```
sudo useradd -m -s /bin/bash adv
sudo passwd adv
```

### Роли в инфраструктуре

В лабораторной работе выделены три машины:

- **`adv-server`** — серверная часть. На ней развёртываются сервисы (например, файловое хранилище,
  DHCP, DNS, HTTP).
- **`advc1`** — первый клиент, подключается к серверу.
- **`advc2`** — второй клиент, подключается к серверу.

Это классическая схема **«клиент-сервер»**: один сервер раздаёт ресурсы и услуги, несколько клиентов
потребляют их. Так строятся сети предприятий, где центральная машина хранит данные и предоставляет
доступ к общим ресурсам.

### Команда `sudo rm -rf /.`

Это **опаснейшая** команда, которая пытается рекурсивно (`-r`) и принудительно (`-f`) удалить всю
корневую файловую систему `/`. В реальной системе она приведёт к полной потере данных и неработоспособности
машины. В лабораторной работе она фигурирует как **антипример** — показывает, чего делать нельзя,
и напоминает о важности работы с правами администратора.

> ⚠️ **Никогда не выполняйте `sudo rm -rf /.` на реальных системах.**
