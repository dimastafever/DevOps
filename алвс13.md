## Теория

### Kubernetes

**Kubernetes** (сокращённо **K8s**) — система оркестрации контейнеров. Она автоматизирует
развёртывание, масштабирование и управление контейнерными приложениями (подами).

Основные понятия:

- **Pod** — минимальная единица в Kubernetes; один или несколько контейнеров, которые
  запускаются вместе на одном узле.
- **Node** — физическая или виртуальная машина, на которой запускаются поды.
- **Control Plane** — компоненты управления кластером (API-сервер, etcd, scheduler,
  controller-manager).
- **Worker Node** — узел, на котором выполняются рабочие нагрузки.
- **kubectl** — командный интерфейс для управления кластером.

### kubeadm

**kubeadm** — инструмент для создания и инициализации Kubernetes-кластера. Он:

- инициализирует control-plane (`kubeadm init`),
- подключает рабочие узлы (`kubeadm join`),
- генерирует сертификаты и конфигурационные файлы.

### Файл kubeadm-config.yaml

Конфигурация описывает параметры кластера. В файле два документа (`kind`):

1. **`InitConfiguration`** — настройки инициализации:
   - `criSocket: "unix:///var/run/dockershim/dockershim.sock"` — сокет для взаимодействия
     kubelet с контейнерным рантаймом. В `v1.24` это указывает на использование
     **dockershim** (embeded Docker) или **cri-dockerd**.
   - `cgroup-driver: "systemd"` — драйвер управления группами процессов (cgroups).

2. **`ClusterConfiguration`** — параметры кластера:
   - `kubernetesVersion: "v1.24.0"` — версия Kubernetes.
   - `controlPlaneEndpoint: "192.168.1.74:6443"` — адрес control-plane (API-сервер).
   - `podSubnet: "10.244.0.0/16"` — подсеть для подов (типична для Flannel).
   - `serviceSubnet: "10.96.0.0/12"` — подсеть для сервисов.
   - `dnsDomain: "cluster.local"` — домен для DNS внутри кластера.
   - `imageRepository: "registry.k8s.io"` — репозиторий образов.

### Инициализация кластера

Команда инициализации:

```
sudo /usr/local/bin/kubeadm init \
  --config /etc/kubernetes/kubeadm-config.yaml \
  --ignore-preflight-errors=all
```

Ключевые флаги:

- `--config` — указание файла конфигурации.
- `--ignore-preflight-errors=all` — игнорировать все предварительные проверки
  (например, занятость портов или наличие старых конфигураций). Это удобно для
  учебной среды.

### Вывод после инициализации

Успешная инициализация даёт инструкцию:

```
Your Kubernetes control-plane has initialized successfully!
```

Далее необходимо:

1. **Настроить kubectl для обычного пользователя:**
   ```
   mkdir -p $HOME/.kube
   sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
   sudo chown $(id -u):$(id -g) $HOME/.kube/config
   ```
   (или для root — `export KUBECONFIG=/etc/kubernetes/admin.conf`)

2. **Развернуть подовую сеть** (pod network):
   ```
   kubectl apply -f [podnetwork].yaml
   ```
   Например, Flannel или Calico.

3. **Подключить рабочие узлы** командой `kubeadm join`:
   ```
   kubeadm join 192.168.1.74:6443 --token g9fcre.jk0j4b71k09dqpp3 \
     --discovery-token-ca-cert-hash sha256:...
   ```

### CRI и Docker в Kubernetes

В Kubernetes kubelet общается с контейнерным рантаймом через **CRI**
(Container Runtime Interface). Исторически использовался **dockershim** — прослойка,
позволяющая Docker работать как CRI-рантайм.

Начиная с **Kubernetes 1.24** dockershim удалён. Вместо него стали использовать
**cri-dockerd** (адаптер для Docker) либо другие рантаймы: **containerd**, **CRI-O**.

> Шутка из файла — *«1 место: новый куб не использует докер... а использует cri-docker»* —
> отражает этот переход: Kubernetes больше не использует Docker напрямую,
> а работает с ним через адаптер `cri-dockerd`.

### Ansible и запуск плейбука

В файле используется Docker-контейнер для запуска Ansible:

```
docker run --rm -e ANSIBLE_HOST_KEY_CHECKING=False \
  -v c:/alvs:/ansible williamyeh/ansible:ubuntu18.04 \
  ansible-playbook -i /ansible/inventory.ini /ansible/playbook.yml
```

Разбор команды:

- `docker run` — запуск контейнера.
- `--rm` — автоматическое удаление контейнера после завершения.
- `-e ANSIBLE_HOST_KEY_CHECKING=False` — переменная окружения, отключающая проверку
  SSH-ключей хостов (чтобы Ansible не запрашивал подтверждение).
- `-v c:/alvs:/ansible` — монтирование локальной директории `c:/alvs` в `/ansible`
  внутри контейнера.
- `williamyeh/ansible:ubuntu18.04` — образ с Ansible.
- `ansible-playbook -i /ansible/inventory.ini /ansible/playbook.yml` — запуск
  плейбука с inventory-файлом.

### Консольный вывод `kubeadm init`

В файле приведён реальный вывод команды `kubeadm init`. Он показывает пошаговый процесс
инициализации:

- **`[preflight]`** — предварительные проверки (предупреждения о занятых портах, наличии
  старых файлов, отсутствии cgroups `blkio`).
- **`[certs]`** — использование/генерация сертификатов.
- **`[kubeconfig]`** — конфигурационные файлы kubectl.
- **`[kubelet-start]`** — запуск kubelet.
- **`[control-plane]`** — создание статических подов control-plane (kube-apiserver,
  kube-controller-manager, kube-scheduler) и etcd.
- **`[wait-control-plane]`** — ожидание готовности control-plane.
- **`[upload-config]`** — сохранение конфигурации в ConfigMap.
- **`[mark-control-plane]`** — маркировка узла как control-plane и наложение taint.
- **`[bootstrap-token]`** — настройка токенов для подключения узлов.
- **`[addons]`** — применение CoreDNS и kube-proxy.

Успешная инициализация завершается сообщением:

```
Your Kubernetes control-plane has initialized successfully!
```

После этого выдаётся команда для подключения рабочих узлов:

```
kubeadm join 192.168.1.74:6443 \
  --token g9fcre.jk0j4b71k09dqpp3 \
  --discovery-token-ca-cert-hash sha256:5c2445614bb70c64f368369d931bae9afbfca7d418dab27eff81c114e4a16868
```

- `--token` — токен аутентификации для рабочих узлов.
- `--discovery-token-ca-cert-hash` — хэш сертификата CA для безопасного подключения.

### Полезные вспомогательные команды

В файле также присутствуют команды подготовки окружения:

```
sudo apt-get install -y conntrack socat
sudo curl -L https://github.com/kubernetes-sigs/cri-tools/releases/download/v1.24.0/crictl-v1.24.0-linux-amd64.tar.gz \
  | sudo tar zx -C /usr/local/bin
```

- **`conntrack`** — утилита для отслеживания сетевых соединений (используется
  компонентами Kubernetes).
- **`socat`** — утилита для работы с сокетами (нужна для проксирования).
- **`crictl`** — CLI для работы с CRI-рантаймами (аналог `docker` для CRI).
